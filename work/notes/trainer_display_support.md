# Full opponent names (D-2487)

The five Chinese group labels in a027/0719 (#17, #59, #632, #666, #745) now retain their complete meaning in English and Spanish. Their catalogue text is the visible name. No game text is embedded in the support module.

`trainer_display.py` creates a locale-specific display plan from the selected EN-shaped workspace. `ws.export` accepts this plan only through its compiler API; the ordinary export command still rejects names that exceed packed storage. The compiler stores unique six-character internal keys, compressed into six units including the terminator, in the existing eight-unit field. It installs the matching formatter before writing and checks both the exported keys and the final native bank. A no-hardcoded build with full names is refused, including under lenient export.

The guarded hook replaces eight bytes at ARM9 0x0202703C (`String_Cat_HandleTrainerName`). It matches the exact packed key units and appends that reference's full name to the existing destination. All other strings replay the original prologue and continue at 0x02027044. This preserves the singular Beedrill trainer at #462 and ordinary Pokémon/player names. The helper appends only if the destination has room for the entire name and terminator. It preserves callee-saved registers and never changes trainer save-data layout or player/nickname limits.

Code and encoded display strings are assembled with the existing pinned armips 0.11 toolchain, appended to aligned ITCM below 0x01FFA000, and covered by payload, catalogue and allocation receipts. The SDK arena boundary moves past the helper. Existing text-speed verification permits only a separately verified tail. Existing assembly verification checks a normalized preceding-stage view, undoing exactly this hook, boundary and tail, so prior hashes and code-region checks remain strict.
